# 进度管理构件化数据设计

## 1. 文档目标

本文档用于沉淀 `进度管理` 模块后续开发所采用的数据设计方案，统一以下实现口径：

- `计划任务` 与 `实际记录` 的主关联链路以构件 `applicationId` 为准
- `形象进度` 和统计能力统一按 `构件` 维度聚合
- 在构件快照基础上补充 `任务快照`，用于高频任务状态查询与统计

本文档优先服务开发实现，不替代产品需求文档。

## 2. 核心业务口径

### 2.1 主对象定义

- `计划任务`：描述一批构件计划什么时候开始、什么时候结束
- `实际记录`：描述一批构件实际上什么时候开始、什么时候完成
- `构件`：以 `modelId + applicationId` 作为唯一识别对象

### 2.2 关联主线

本模块不采用“实际记录挂某个计划任务”的主模型，而采用“计划与实际都指向构件”的主模型：

- 计划侧通过任务绑定构件
- 实际侧通过开始构件和完成构件回填
- 形象进度和统计按构件聚合
- 任务状态通过任务所绑定构件的聚合结果反推

### 2.3 多任务同构件口径

当一个构件同时关联多个计划任务时：

- `构件计划开始时间` 取所有命中任务 `planStart` 的最小值
- `构件计划完成时间` 取所有命中任务 `planEnd` 的最大值

该口径用于构件快照计算。

### 2.4 实际回填口径

实际进度录入明确拆成两类事件：

- `今日开始施工构件`
- `今日完成构件`

对应到结构化数据时：

- 开始构件产生 `start` 事件
- 完成构件产生 `finish` 事件

## 3. 当前基础结构

### 3.1 计划任务

当前计划任务以 `project_progress_plan_tasks` 为主表，`bimElements` 主口径为多模型 `selections`：

```ts
type ProgressPlanTaskBimSelection = {
  modelId: string
  applicationIds: string[]
}

type ProgressPlanTaskBimElements = {
  modelId: string | null
  modelIds: string[]
  applicationIds: string[]
  selections: ProgressPlanTaskBimSelection[]
}
```

说明：

- `selections` 是主编辑口径
- `modelIds`、`applicationIds` 是便于列表和统计的冗余汇总

### 3.2 实际记录

当前实际记录以 `project_progress_actual_records` 为主表，已拆为两套多模型结构：

```ts
type ProgressActualRecordBimSelection = {
  modelId: string
  applicationIds: string[]
}

type ProgressActualRecordBimElements = {
  modelId: string | null
  modelIds: string[]
  applicationIds: string[]
  selections: ProgressActualRecordBimSelection[]
}
```

当前实际记录包含：

- `startBimElements`
- `finishBimElements`
- `bimElements` 兼容字段

说明：

- `startBimElements` 表示今日开始施工构件
- `finishBimElements` 表示今日完成构件
- `bimElements` 仅用于兼容旧口径，后续不再作为主计算来源

## 4. 目标数据架构

后续开发统一采用五层结构：

1. `project_progress_plan_tasks`
2. `project_progress_actual_records`
3. `project_progress_task_elements`
4. `project_progress_actual_element_events`
5. `project_progress_element_snapshots`
6. `project_progress_task_snapshots`

其中：

- 前两张表保留原始录入信息
- 中间两张表负责把任务和记录展开成“构件明细”
- 后两张表负责固化构件状态和任务状态

## 6. 状态计算规则

### 6.1 构件快照计算

对单个 `(projectId, modelId, applicationId)`：

- `plannedStartAt`
  - 取 `project_progress_task_elements` 中命中该构件的最小 `planStart`
- `plannedFinishAt`
  - 取 `project_progress_task_elements` 中命中该构件的最大 `planEnd`
- `actualStartAt`
  - 取 `project_progress_actual_element_events` 中 `eventType = start` 的最早 `eventAt`
- `actualFinishAt`
  - 取 `project_progress_actual_element_events` 中 `eventType = finish` 的最晚 `eventAt`
- `lastReportAt`
  - 取全部事件最大 `eventAt`

### 6.2 构件状态枚举

建议统一使用以下枚举：

- `not_started`
- `ready_not_started`
- `delayed_not_started`
- `in_progress`
- `in_progress_delayed`
- `finished_ahead`
- `finished_on_time`
- `finished_delayed`

判定规则：

- `not_started`
  - `actualStartAt` 与 `actualFinishAt` 都为空，且当前时间早于 `plannedStartAt`
- `ready_not_started`
  - `actualStartAt` 与 `actualFinishAt` 都为空，且当前时间已进入计划窗口但尚未超过 `plannedFinishAt`
- `delayed_not_started`
  - `actualStartAt` 与 `actualFinishAt` 都为空，且当前时间已超过 `plannedFinishAt`
- `in_progress`
  - `actualStartAt` 不为空且 `actualFinishAt` 为空，且当前时间未超过 `plannedFinishAt`
- `in_progress_delayed`
  - `actualStartAt` 不为空且 `actualFinishAt` 为空，且当前时间已超过 `plannedFinishAt`
- `finished_ahead`
  - `actualFinishAt` 不为空，且 `< plannedFinishAt`
- `finished_on_time`
  - `actualFinishAt` 不为空，且 `= plannedFinishAt`
- `finished_delayed`
  - `actualFinishAt` 不为空，且 `> plannedFinishAt`

补充规则：

- 只要 `actualFinishAt` 存在，就优先判定为“已完成”类状态
- `progressStatus` 需要综合 `actualStartAt`、`actualFinishAt`、`plannedStartAt`、`plannedFinishAt` 和当前时间判断

前端颜色建议：

- `finished_on_time`：蓝色
- `finished_ahead`：绿色
- `finished_delayed`：红色
- `in_progress`：橙色
- `in_progress_delayed`：深橙色
- `ready_not_started`：深灰色
- `not_started`：灰色
- `delayed_not_started`：深红色

### 6.3 构件统计辅助字段

- `progressPercent`
  - 第一版建议采用简单口径：
    - `not_started / ready_not_started / delayed_not_started`：`0`
    - `in_progress / in_progress_delayed`：可先固定为 `50`，或直接为空由前端单独展示
    - 所有已完成状态：`100`
- `isAheadStart`
  - `actualStartAt < plannedStartAt`
- `isDelayedFinish`
  - `actualFinishAt > plannedFinishAt`

## 7. 任务快照计算规则

### 7.1 任务快照来源

任务快照由以下数据反推：

- `project_progress_plan_tasks`
- `project_progress_task_elements`
- `project_progress_element_snapshots`

### 7.2 任务聚合字段

对单个任务 `taskId`：

- `totalElementCount`
  - 该任务绑定构件总数
- `finishedElementCount`
  - 该任务绑定构件中 `actualFinishAt` 不为空的数量
- `inProgressElementCount`
  - 该任务绑定构件中状态为 `in_progress` 的数量
- `notStartedElementCount`
  - 该任务绑定构件中状态为 `not_started` 的数量
- `delayedElementCount`
  - 该任务绑定构件中状态为 `finished_delayed` 的数量
- `completionRate`
  - `finishedElementCount / totalElementCount`
- `plannedStartAt`
  - 直接取任务自己的 `planStart`
- `plannedFinishAt`
  - 直接取任务自己的 `planEnd`
- `actualStartAt`
  - 任务绑定构件中最小 `actualStartAt`
- `actualFinishAt`
  - 任务绑定构件中最大 `actualFinishAt`

### 7.3 任务状态枚举

建议统一使用以下枚举：

- `no_bim_link`
- `not_started`
- `in_progress`
- `delayed`
- `finished_on_time`
- `finished_delayed`

判定规则：

- `no_bim_link`
  - 任务未绑定任何构件
- `not_started`
  - 已绑定构件，但全部构件都未开始
- `in_progress`
  - 已有部分构件开始，但未全部完成，且当前时间未超过 `plannedFinishAt`
- `delayed`
  - 未全部完成，且当前时间已超过 `plannedFinishAt`
- `finished_on_time`
  - 全部构件完成，且 `actualFinishAt <= plannedFinishAt`
- `finished_delayed`
  - 全部构件完成，且 `actualFinishAt > plannedFinishAt`

### 7.4 哪些任务已完成、哪些任务已逾期

该设计可直接支持以下统计：

- 已完成任务
  - `taskStatus in ('finished_on_time', 'finished_delayed')`
- 按期完成任务
  - `taskStatus = 'finished_on_time'`
- 延期完成任务
  - `taskStatus = 'finished_delayed'`
- 逾期未完成任务
  - `taskStatus = 'delayed'`
- 进行中任务
  - `taskStatus = 'in_progress'`
- 未开始任务
  - `taskStatus = 'not_started'`

## 8. 数据写入与重算流程

### 8.1 计划任务更新

触发时机：

- `.mpp` 导入
- 手动更新任务 BIM 关联

流程：

1. 保存 `project_progress_plan_tasks`
2. 删除该任务旧的 `project_progress_task_elements`
3. 将 `bimElements.selections` 展开重建 `project_progress_task_elements`
4. 收集受影响构件
5. 重算受影响 `project_progress_element_snapshots`
6. 反查受影响 `taskId`
7. 重算受影响 `project_progress_task_snapshots`

### 8.2 实际记录新增或编辑

触发时机：

- 新增实际记录
- 编辑实际记录

流程：

1. 保存 `project_progress_actual_records`
2. 删除该记录旧的 `project_progress_actual_element_events`
3. 将 `startSelections` 展开为 `eventType = start`
4. 将 `finishSelections` 展开为 `eventType = finish`
5. 收集受影响构件
6. 重算受影响 `project_progress_element_snapshots`
7. 反查受影响任务
8. 重算受影响 `project_progress_task_snapshots`

### 8.3 实际记录删除

流程：

1. 查询该记录涉及的构件
2. 删除 `project_progress_actual_element_events`
3. 删除 `project_progress_actual_records`
4. 重算受影响 `project_progress_element_snapshots`
5. 重算受影响 `project_progress_task_snapshots`

## 9. 建议封装的服务

### 9.1 任务构件展开服务

建议命名：

- `syncTaskElementsFromPlanTaskFactory`

职责：

- 将任务的 `selections` 展开成 `project_progress_task_elements`

### 9.2 实际事件展开服务

建议命名：

- `syncActualElementEventsFromRecordFactory`

职责：

- 将实际记录的 `startSelections` / `finishSelections` 展开成事件表

### 9.3 构件快照重算服务

建议命名：

- `rebuildProgressElementSnapshotsFactory`

输入建议：

```ts
type ProgressElementRef = {
  modelId: string
  applicationId: string
}
```

职责：

- 按构件维度重算 `plannedStartAt`、`plannedFinishAt`、`actualStartAt`、`actualFinishAt`
- 更新 `project_progress_element_snapshots`
- 若计划和实际都不存在，可删除对应快照

### 9.4 任务快照重算服务

建议命名：

- `rebuildProgressTaskSnapshotsFactory`

职责：

- 根据任务绑定构件及构件快照，重算任务维度状态和统计字段

## 11. 前端页面使用建议

### 11.1 进度计划页

- 继续维护任务原始结构和 `selections`
- 不直接参与构件快照和任务快照计算

### 11.2 实际进度页

- 继续维护 `startSelections`
- 继续维护 `finishSelections`
- `taskName` 仅作为记录标题或说明字段，不作为主关联键

### 11.3 形象进度页

- 不直接运行时聚合计划任务和实际记录
- 统一读取 `element-snapshots`
- 将 `(modelId, applicationId) -> progressStatus` 映射为 Viewer 着色

### 11.4 任务维度页面或统计区

- 不直接运行时聚合构件
- 统一读取 `task-snapshots`

## 13. 第一版边界建议

第一版建议采用以下简化口径：

- 构件计划完成时间按命中任务 `planEnd` 最大值
- 任务完成判定按“绑定构件全部完成”
- 构件完成度不做复杂百分比推导
- 不做关键路径计算
- 不做任务级自动排程
- 不做复杂工序依赖推理

## 14. 最终结论

后续开发统一采用以下主线：

- 用 `计划任务` 维护构件计划时间来源
- 用 `实际记录` 维护构件开始/完成事件来源
- 用 `任务构件明细` 和 `实际构件事件` 将原始数据展开
- 用 `构件快照` 支撑形象进度与构件统计
- 用 `任务快照` 支撑任务完成、逾期、完成率等统计

这样可以同时满足：

- 构件维度着色
- 计划与实际对比
- 任务维度完成/逾期统计
- 后续继续扩展更细颗粒度分析
